- 재조회: 새로고침 후 현재 버전 이력 1건, 판정·별칭·메모·버전 유지. 독립 과업 판정은 계속 failure.

| 결과물 | 실제 확인 |
|---|---|
| JSON | 다운로드 카드 전체가 재조회 API 카드와 일치 |
| CSV | 실행·카드 ID, 버전, 판정, 별칭, 메모, 검토 상태 일치 |
| Markdown / HTML | 현재 카드 ID·버전, 판정, 별칭, 메모 일치 |

JSON/CSV/Markdown은 앱 내 브라우저에서 다운로드했다. HTML은 앱 내 브라우저 다운로드 도구가 시간 초과되어 같은 실행을 별도 Chromium 회귀 검증으로 열고 링크를 눌러 다운로드했다. 해당 파일도 동일 필드 대조에 통과했다. 앱 내 브라우저 HTML 다운로드 자체의 성공은 주장하지 않는다.

## 발견한 문제와 수정

검토 후 근거가 바뀌면 Markdown/HTML에 현재 근거 버전이 없어 현재 카드와 이전 검토를 식별하기 어려웠다. 실패 재현 테스트를 먼저 추가하고, 모든 카드의 현재 ID·근거 버전을 내보내도록 수정했다. 이전 버전 판정은 현재 최신 판정으로 적용하지 않는다.

새 브라우저 회귀 검사 `tests/test_review_export_browser.py`는 유효·보류 판정 저장, 390px 화면, 새로고침, 네 형식 다운로드 대조, 쉼표·따옴표·줄바꿈·HTML 문자, 근거 변경 후 이전 판정 비적용을 확인한다.

## 팀원 재현 절차

현재 브랜치: `codex/36-review-export-verification`. PR head 커밋을 기록하고 실행한다. Windows에서는 Python 경로를 `.venv/Scripts/python.exe`로 바꾼다.

```sh
.venv/bin/python -m uxagent doctor --study configs/study.json
.venv/bin/python -m uxagent scenario --config configs/scenarios/decathlon-flow.json --defect filter
.venv/bin/python -m uxagent dashboard
```

1. 대시보드 실행 기록에서 방금 생성한 실행을 선택한다.
2. 개선 보드의 조건 필터 적용 후보에서 행동 6 근거 보기를 누른다. 선택된 조건과 실제 상품 목록을 대조한다.
3. 개선 보드로 돌아와 테스트 별칭·판정·메모를 저장한다.
4. 새로고침하고 개선 보드에서 현재 버전 이력을 펼친다. 저장한 값과 버전을 확인한다.
5. 실행 기록 → 자료 내보내기에서 네 형식을 다운로드한다. 동일 카드의 ID·버전·최신 판정·별칭·메모를 대조한다. CSV는 CSV 파서/스프레드시트로 읽어 따옴표와 줄바꿈을 보존한다.
6. 아래 회귀 검사를 실행하고 재현자·OS·커밋·결과를 PR에 남긴다.

```sh
.venv/bin/python -m pytest -q tests/test_review_export_browser.py tests/test_review_form_browser.py tests/test_comparison_browser.py
```

macOS 임시 폴더를 쓸 경우 `--runs /private/tmp/...`처럼 심볼릭 링크 없는 실제 경로를 쓴다. `/tmp`는 심볼릭 링크라 검토 저장소의 경로 안전 검사에 거절될 수 있다. 경로 검사를 완화하지 않았다. 상세 조회 실패가 빈 후보처럼 보이는 문제는 기존 추가 개선 후보로 남긴다.
