# D: Brain 기록 화면·보고서 소비 (#47)

2026-10-15 작업 브랜치 `codex/47-brain-trace-viewer`, 선행 D 안정화 PR #67. 생성 파일 계약은 A의 PR #48/#53/#63 및 Slow 작업 계약을 따른다. 생성 실행기 전체를 이 브랜치로 교체하지 않는다.

## 읽는 자료와 표시

- `brain_stages.jsonl`: perception/plan/decision/importance/reflection/plan_review/wonder 생성 결과와 기록 ID·관찰·계획 버전·기억 출처·snapshot.
- `brain_tasks.jsonl`: 작업별 마지막 append 사건을 예약/진행/완료/생략/실패/취소로 구분한다. 시각을 정렬해 이전 상태로 되돌리지 않는다. 전체 사건도 API/내보내기에 보존한다.
- `memory.jsonl`: 원본 기억과 1.0(0–5)/2.0(1–10) 점수 척도. 미산정은 0으로 바꾸지 않는다.
- `memory_changes.jsonl`: 중요도 갱신과 활성 목록 제거를 overlay한다. 제거된 기억도 원본 텍스트·ID·순번을 읽을 수 있다. 원본 파일은 수정하지 않는다.

실행 기록의 접힌 ‘AI 생성·비동기 기록’에서 확인한다. 현재 상세에 관찰이 있으면 단계 생성에 사용한 정확한 관찰을 볼 수 있다. 단계·작업·기억의 펼침은 같은 실행의 자동 갱신에서 유지한다. AI 생성물·행동 제안은 실행된 행동이나 독립 평가·사람 검토·사람의 생각으로 표시하지 않는다. 완료 사건만으로 후속 계획에 반영됐다고 추정하지 않는다. 실제 반영 연결은 #43/#44 생성 계약이 기록한 근거로 후속 검증한다.

파일 없음은 구버전 지원이며 생성 성공으로 보지 않는다. 잘못된 JSON·다른 실행 ID·지원하지 않는 버전·잘못된 단계/상태·심볼릭 링크는 경고와 함께 제외한다. 미완성 append 행도 조용히 성공 처리하지 않는다. 누락된 원본 기억 출처는 표시하며 다른 실행에서 대신 찾지 않는다.

## 출력 호환

JSON은 `brain` 필드를 추가한다. Markdown/HTML은 AI 기록 별도 구역을 추가하며 HTML 텍스트는 escape한다. Brain 파일이 없는 기존 CSV는 열 구성을 유지한다. Brain 파일이 있는 CSV는 기존 카드 열 뒤 `record_type,record_id,brain_record`를 추가한다.

- 카드 행: record_type=candidate.
- 추가 행: brain_stage/brain_task_event/memory/memory_change/brain_warning.
- brain_record는 CSV 규칙으로 인코딩한 JSON이다. 분석 시 record_type으로 행을 구분해야 한다. 카드 ID가 없는 행을 후보로 세지 않는다.

원문 기록은 API와 모든 출력에서 기존 비밀값 제거를 적용한다. 모든 문자열은 텍스트 데이터로 처리하며 CSV 수식 실행과 HTML 삽입을 방지한다. 후보 버전은 Brain 기록 추가만으로 바뀌지 않고 독립 verification과 기존 집계 분모도 변경하지 않는다.
