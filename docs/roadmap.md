# 개발 순서

## 현재 진행 상태

1차 최소 구현은 로컬 mock에서 설정 → 검색·필터·상세 판정 → 대응 비교 → 근거 → 미검토 카드·출력까지 연결됐다. 남은 실제 사이트 검증·구독 PoC·자유 대화·세부 탐색·사람 검토는 이슈로 분리한다. 아래 순서는 후속 개선에서도 유지하며 이미 구현된 부분을 다시 만들지 않는다.

## 완료한 준비와 앞으로 할 기능

저장소 문서·지침·CI·이슈 설정은 기능 완성을 뜻하지 않는다. 우선 기존 mock 흐름을 기준선으로 검증하고 다음 순서로 최소 제품을 완성한다. 1차 시연 목표는 2026-10-16이다.

| 순서 | 작업 | 선행 | 완료 결과 |
|---|---|---|---|
| 0 | 저장소·문서·검증 환경 | 없음 | 이슈·CI·AI 진입 문서·로컬 baseline |
| 1 | 기존 실행 안정화·후보/결과 처리 | 0 | 확인된 회귀 수정, 기존 mock 유지 |
| 2 | 과업·기능별 독립 평가 | 1 | 검색/필터/상세 결과를 근거로 판정 |
| 3 | 세션 등록·지표·복구/기록 분석 | 2 | 분모가 고정된 결과 데이터 |
| 4 | 일반 AI·persona AI 대응 비교 | 3 | 조건 차이가 persona뿐인 비교 |
| 5 | 쉬운 연결·설정 | 1 | API 키 기본 경로, 구독 경로 가능성 검증 |
| 6 | 테스트·비교 대시보드 | 3,4,5 | 사용자가 두 결과를 클릭해 근거 조회 |
| 7 | 개발자 개선 카드·내보내기 | 3,6 | 실제 개선 작업으로 옮길 결과 |
| 8 | 통합 시연 검증 | 2~7 | 정상·실패 사례와 한계 설명 가능한 발표 |

## 최소 제품 범위

- 대표 과업 1개에 검색·필터 적용/해제·상품 정보 확인의 하위 점검.
- persona 2종·환경 1개, 조건별 3회 반복 제안(비용 예비 검사 후 고정).
- 과업 테스트와 AI 비교 화면, 설정 확인, 중지, 근거, 미검토 개선 카드, 출력.
- 기존 Python 실행기 유지. API 키 경로는 기본 지원; ChatGPT 구독 연결은 적격 로컬 앱 PoC를 먼저 수행하고 지원 확인 후 노출.
- 사람이 확정하지 않은 후보를 확정 UX 문제로 표시하지 않음.
