# 2026-10-16 prototype squash 병합 준비

## 요청과 현재 원격 상태

사용자는 처음 develop을 요청한 뒤 prototype에 순차 squash 병합하고 병합 완료한 브랜치를 삭제하도록 정정했다. 리뷰 대기와 무관하게 가능한 것을 최대한 병합하도록 요청했다.

원격 prototype은 `9323df5`다. 필수 승인 1명, 관리자 적용, 최신 base 요구와 Ubuntu/Windows 필수 CI가 설정돼 있다. #30 직접 관리자 squash 요청은 승인 1명이 없어 GitHub가 거부했다. 승인 수만 병합 중 0으로 바꾸고 즉시 복원하는 요청도 자동 승인 검토에서 거절됐다. 이유는 병합 요청과 보호 설정 변경 허용이 구분된다는 것이다. 보호 설정 변경을 명시적으로 허용할지 사용자 답변을 기다린다. 이 거절을 우회하지 않으며 현재까지 원격 병합·브랜치 삭제·보호 설정 변경은 없다.

#37의 base만 선행 #30의 브랜치 삭제에 대비해 prototype으로 변경했다. 다른 원격 PR의 코드/상태는 변경하지 않았다. 기본 브랜치는 main이고 develop은 조회 당시 존재하지 않았다.

실제 병합 때는 각 단계의 최신 head·base·CI·충돌을 다시 확인한다. squash는 원래 commit ancestry를 유지하지 않으므로 다음 PR의 base를 prototype으로 옮기고, 이전 코드와 새 통합 코드를 실제 diff로 확인한다. 선행 브랜치를 삭제하기 전에 그 브랜치를 base로 둔 PR을 먼저 옮긴다. 각 원본 작성자·기여 출처를 squash 메시지에 보존한다. 병합되지 않은 작업 브랜치는 삭제하지 않는다.
