# [phase:1] 활성 메모리 제거 경계와 비동기 출처 보호

GitHub: [#55](https://github.com/2026-2-1/Persona/issues/55)

## 상한 안의 보호 순서

`max_active_memories`는 10~64개이며 초과를 허용하지 않는다. 추가 시 제거 대상의 우선순위는 다음 순서로 결정한다. 높은 순서의 기억을 더 오래 보존한다.

1. 현재 Fast 단계의 원본 관찰·생성 인식·계획 기억
2. 최신 10개의 과업 기억
3. 중요도 산정 대기 기억
4. 진행 중 Slow snapshot의 입력 기억
5. 나머지 기억: 중요도 높은 순, 동점이면 최신 순번

Wonder는 모든 과업 기억보다 먼저 제거한다. N=10에서 현재 단계 기억이 최신 10개 밖으로 밀리면 현재 단계 기억을 남기고 최신 10개 중 하나를 제거할 수 있다. 중요도 대기 또는 Slow snapshot 기억이 최신 10개보다 오래되면 제거될 수 있다. 이때 `pending_importance_capacity`, `slow_snapshot_capacity`, `recent_capacity_for_current_stage` 등 제거 이유를 사건으로 남긴다. 실패하거나 끝난 중요도 시도는 더 이상 대기 보호를 받지 않는다.

## 출처와 캐시

- Slow는 입력을 깊은 복사한 snapshot과 원본 memory ID·`snapshot_seq`를 작업·단계 기록에 남긴다. 활성 목록에서 제거되어도 원본 `memory.jsonl`과 제거 사건은 남고, 늦은 점수는 제거된 ID에 적용되지 않는다.
- 제거 시 해당 memory ID의 embedding cache를 삭제한다. 진행 중인 임베딩 요청이 나중에 돌아와도 현재 활성 ID에 대해서만 캐시한다.
- 현재 Fast 단계 기억 보호는 단계 중에 갱신하고, decision 완료 또는 실행 종료 때 해제한다.

## 검증과 제한

- N=10의 현재 단계와 최신 10개 충돌, N=12의 대기 점수 보존, 대기 기억 제거 이유, 오래된 Slow snapshot 출처, 임베딩 요청 중 제거를 회귀 검사한다.
- 원본 UXAgent에는 이 프로젝트의 활성 기억 10~64개 상한이 없다. 이 우선순위는 프로젝트의 유한 메모리 조건에서 출처를 보존하기 위한 정책이다.
