## 검색·필터의 접근성 구조

- 검색 입력은 홈페이지에서 유일한 `textbox`였다. 당시 placeholder는 `리뷰 작성 시 즉시 사용 가능한 2,000포인트 증정!`였다. 마케팅 문구이므로 안정된 검색 라벨로 가정하지 않는다.
- 검색 제안에 `다음에 대한 모든 결과 보기 "러닝화 "` 링크가 관찰됐다. Enter 이후 비동기 이동 중 사라져 이 링크 클릭은 `no element matched`로 끝났다. 이후 실제 검색 결과 도착을 확인했다. 이 실패를 검색 실패나 링크 자체의 UX 결함으로 확정할 수 없다.
- 필터는 button 역할로 `제품 특성`, `색상`, `성별`, `브랜드`, `사이즈`, `스포츠`, `가격`이 노출됐다. 가격 외 선택·해제, 정렬 적용, 빈 결과 상태는 이번 조사에서 검증하지 않았다.
- 가격 펼침은 button의 expanded 상태와 region `가격`으로 확인됐다. slider 2개는 동일한 `Accessibility label`, 숫자 입력 2개는 라벨 없는 `spinbutton`이었다. 화면 순서로 `Min` 14900, `Max` 269000을 확인했다.
- 두 가격 input의 실제 DOM 속성은 모두 `data-testid="price-filter-input"`, `type="number"`였다. 별개의 접근성 이름이 없어 최신 관찰에서 순서와 가까운 Min/Max 문맥을 확인해야 한다. 임의 전역 nth나 고정 CSS 해시만으로 목표를 선택하면 다른 숫자 입력과 혼동할 수 있다.
- 최대값 80000 적용 후 펼침 버튼 이름은 `가격 From 14,900원 to 80,000원`으로 바뀌었다. 적용 상태에서 정확히 `가격`만 찾는 코드는 재탐색 때 실패할 수 있다.
- 선택 필터 해제 버튼 `모두 지우기 (1)`은 보였지만 클릭하지 않았다.

## 상품 카드와 상세

추가 DOM 확인으로 다음 속성을 실제 페이지에서 확인했다. 선택자는 당시 렌더링된 DOM에만 근거하며 사이트 변경에 영구 안정성을 보장하지 않는다.

| 용도 | 관찰된 선택자 / 속성 |
|---|---|
| 데스크톱 검색 | `[data-cy="search-bar-desktop"] input` — 입력 부모에 data-cy 존재 |
| 카드 컨테이너 | `[data-testid="producthit-tile-box"]` |
| 카드 바깥 링크 | `a[data-cy="productTile"]` — 내부 색상 링크와 구분 |
| 카드명 | 카드 안 `div[title]` — title와 렌더링 텍스트가 상품명 |
| 카드 현재 가격 | 카드 안 `[data-cy="item-current-price"]` |
| 카드 브랜드 / 평점 | `[data-testid="product-tile-brand"]` / `[data-testid="productHitReviewStarBox"]` |
| 관찰 상품 클릭 | `a[data-cy="productTile"][href*="-8926930.html"]` |
| 상세 제목 | `h1` |
| 상세 주요 가격 | `[data-cy="item-current-price"].vp-price-amount--large` — sticky/본문 두 번, 같은 가격 |
| 상세 사이즈 | `input[role="combobox"][aria-readonly="true"]` — 미선택 상태 |
| 사이즈 필요 안내 | `[data-testid="availability-info-text"]` — `사이즈 선택` |

선택 가격 칩의 부모 class는 `filterOption_filterOptionContainer__o_NZD`였다. 칩 button에 고정 test ID는 없고 동적 ID만 있어 가격 텍스트와 URL 조건을 함께 확인해야 한다. 무료배송 span은 `css-k63mnn`만 있었으므로 장기 고정 selector로 권장하지 않는다. 지원이 확인되지 않은 필드의 선택자를 추정하지 않는다.

검색 카드 링크 접근성 이름은 상품명, 현재 가격, 브랜드, 평점, 리뷰 수를 포함했다. 예: `남성 러닝화 킵코어 79,900원 남성 러닝화 킵코어 KIPRUN 4.7 (5505)`. 동일 상품명·가격의 여러 색상 모델이 있어 이름만으로 단일 상품을 식별할 수 없다. 카드 내부에도 색상 변형 `/p/` 링크가 중첩되어 있으므로 모든 `/p/` 링크를 상품 카드 수로 계산하면 중복된다.

상세는 검색 화면의 첫 카드에서 실제 이동했다. 확인한 공개 경로는 `/p/남성-러닝화-킵코어-kiprun-8926930.html`이며 브라우저에서는 한글이 퍼센트 인코딩되고 검색 추적 파라미터가 붙었다.

| 상세 필드 | 실제 표시 | 판정 한계 |
|---|---|---|
| 상품명 | h1 `남성 러닝화 킵코어` | 관찰한 한 상품 |
| 브랜드 / 모델 | KIPRUN / `모델번호: 8926930` | 모델번호로 색상 변형 구분 가능 |
| 가격 | 79,900원 | 화면에 여러 번 반복; 관련 추천 상품·합계와 혼동 금지 |
| 평점 | 4.7 (5505) | 페이지 표시값이며 리뷰 진위 검증 아님 |
| 색상 | `색상:`과 변형 이미지 링크 | 현재 색상명 텍스트는 관찰되지 않음. 검정 조건 성공으로 선언할 수 없음 |
| 사이즈 | h4 `사이즈:`, `사이즈를 선택하세요`, combobox | 미선택. 옵션 목록·재고는 열어보지 않음 |
| 배송 | `50,000원 이상 무료배송`; 먼저 사이즈를 선택하라는 안내 | 특정 사이즈의 발송·재고 가능 여부 미확인 |
| 매장 | `매장 재고 찾기`, `매장 선택` disabled | 픽업 가능 성공 조건 미확인 |
| 사용 설명 | `일상과 러닝`, 매일 착용 가능한 러닝화 설명 | 판매자가 표시한 설명; 실제 성능 검증 아님 |

`장바구니 담기`, `장바구니에 제품 추가` 버튼과 함께 구매하기 체크박스는 관찰만 했다. 실행하지 않았다. combobox는 실제 DOM에서 `aria-readonly="true"`, `aria-autocomplete="list"`인 React custom input이었다. 일반 native select 처리로 지원된다고 가정하지 않는다.

## 접근 문제와 회귀 확인

증상 → 최초 탭 생성이 30초 제한으로 종료됐고, 클릭 직후 관찰이 기존 페이지를 반환한 경우가 있었다.

원인 → 최초 접근 지연의 원인은 확인하지 못했다. UI 탐색·필터 적용은 실제 비동기 이동/Loading 상태가 관찰됐다. 보안 차단이나 CAPTCHA 화면은 관찰되지 않았다.

해결 → 최초 탭 생성 재시도로 홈페이지 접근을 확인했다. 이후 목표 화면의 문구와 URL을 확인한 다음 행동했다. DOM 밖의 앱 상태·네트워크 우회·숨긴 API는 읽지 않았다.

함께 확인할 회귀 → 최신 observation에 묶인 목표 ID 유지, 이동 후 재관찰, 가격 spinbutton과 상세 수량 spinbutton 혼동 방지, 추천 상품을 결과 카드로 오인하지 않기, 가격 current/original/합계 구분, 적용 상태에서 이름이 바뀌는 필터, 미관찰 색상/재고/픽업을 unknown으로 보존하기.

실제 검증 결과 → 본 조사 브라우저에서는 공개 검색·가격 적용·한 상품 상세 도착을 직접 확인했다. Persona 실행기 live end-to-end·모델 호출·API 인증은 수행하지 않았다. 별도 재현 페이지 테스트는 이 관찰의 live 검증을 대신하지 않는다.
