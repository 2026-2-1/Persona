# 연구 주제의 선행 근거와 차별화 후보 — 2026-10-15

## 판단과 범위

**두 루프, 비동기 성찰, 중요도·관련성·최신성 검색, 성찰 제거 비교 자체는 선행 연구가 있다.** 단순 실행 빈도·가중치 튜닝만으로 충분한 논문 Novelty가 확보됐다고 쓰지 않는다. 현재 제안은 기존 구조를 바탕으로 **페르소나 웹 과업에서 비동기 실행 정책의 결과와 비용을 재현 가능한 방식으로 비교하는 실증 연구 후보**다. 연구 공백과 학술적 차별성은 추가 관련연구 검토와 실제 결과로 확인해야 한다.

사용자는 기업체 데이터셋을 **미수령**이라고 확인했다. 기업체 제공 데이터, 실제 사용자 행동·판정, 기업 실무 검증을 확보했다고 쓰지 않는다. 현재 합성 fixture·Mock 실행과 향후 실제 모델 실험도 구분한다. 이 조사에서는 원문을 읽었으며 유료 API·사람 실험·논문 결과 재현을 수행하지 않았다.

## 원문에서 확인한 선행

| 연구와 확인 구간 | 확인한 내용 | 우리 주장에 주는 제한 |
|---|---|---|
| [UXAgent v3, §3.2.1·§4·§5.4](https://arxiv.org/html/2504.09407v3) | Fast/Slow가 메모리를 공유하며 비동기로 작동한다. Fast는 최신성, Slow는 관련성을 강조하며 중요도는 비동기로 산정한다. 연구자 대상 평가는 있지만 실제 사람과 에이전트의 쇼핑 행동을 정량 비교하지 않았다는 한계를 명시한다. | 페르소나·브라우저·두 루프·결과 뷰어를 새 구조라고 주장하지 않는다. Slow 중요도 우선은 우리 가설이다. 원 논문의 사람 비교 한계가 우리 연구에서 자동 해결되지는 않는다. |
| [Generative Agents v2, §4.1·§4.2·§6.2](https://arxiv.org/html/2304.03442v2) | 중요도·관련성·최신성을 이용해 기억을 검색하고 성찰을 기억에 저장한다. 누적 중요도 150을 성찰 발동 기준으로 사용했으며, 성찰·계획 등을 제거한 조건을 비교한다. | 성찰 on/off ablation과 중요도 기반 트리거는 선행이다. 그 기준값·게임 시간 단위·행동의 그럴듯함 평가는 웹 과업에 그대로 이식할 수 없다. |
| [Reflexion v4, §3·§4.3·Appendix B.1](https://arxiv.org/html/2303.11366v4) | 실패 뒤 언어 피드백을 기억해 다음 시도에 사용하며 모델 가중치를 갱신하지 않는다. 자체 성찰 제거 비교가 있고, WebShop에서는 ReAct에 비해 뚜렷한 개선을 보이지 않았다고 보고한다. | 성찰이 항상 유리하다고 가정하지 않는다. 시도 사이 학습과 한 세션 내부 비동기 성찰을 같은 처리로 부르지 않는다. 원문 표현은 “fails to significantly outperform”이며, 해당 부록만으로 통계적 등가나 보편적 무효과를 결론내리지 않는다. |
| [DPT-Agent v2, §4.1.2·§4.2·§5–6](https://arxiv.org/html/2502.11882v2) | 비동기 성찰이 행동 지침을 갱신하고 FSM 기반 System 1이 실행한다. 게임 환경에서 성능·지연을 비교하며 ToM 제거 조건도 평가한다. | 비동기 성찰과 성능·지연 균형 자체는 선행이다. 확인한 구간에서 동일 구조의 `off / 5행동마다 / 매행동` 순수 빈도 실험이나 조건별 동일 API 예산 비교는 확인하지 못했다. 이를 연구 공백의 확정 증거로 삼지는 않는다. |
| [PlanFence v2, §3–4·§6](https://arxiv.org/html/2609.03340v2) | 계획에 실제 전달된 입력 버전의 링크를 남기고, 실행 전 관련 입력의 현재 버전과 비교해 재계획·차단한다. 분산 에이전트의 통제된 변경 상황과 replay에서 조정 시점·범위의 비용을 비교한다. | 늦은 계획의 출처·버전 검증을 새 원리라고 주장하지 않는다. 최신 기억을 읽는 것과 오래된 입력으로 만든 계획이 유효한 것은 별개라는 설계 근거로 활용한다. 페르소나 웹 UX 성과로 일반화하지 않는다. |

추가로 [FlashEvolve v1 §3.1–3.2](https://arxiv.org/html/2605.08520v1)는 에이전트 진화 파이프라인에서 산출물 버전을 추적하고, 오래된 산출물을 그대로 사용·폐기·수정하는 정책을 구분한다. 따라서 비동기 작업의 버전차·취소·폐기 비용을 다루는 것만으로도 최초성은 성립하지 않는다. 다만 프롬프트·프로그램 진화의 처리량과 현재 웹 세션의 성찰 빈도는 평가 대상이 다르다.

위는 범위를 좁힌 원문 조사다. “확인하지 못했다”는 선행이 없다는 뜻이 아니다. 제출 시점에는 같은 문제의 최신 논문·코드까지 다시 확인한다.

## 제안할 수 있는 기여

잠정 주제는 **「페르소나 기반 웹 에이전트의 비동기 성찰 실행 정책과 메모리 검색 정책에 대한 비용·행동 분석」**이다. 제목과 아래 기여는 연구 계획이며 성능 향상이나 Novelty의 확정 주장이 아니다.

1. **원인을 분리하는 비교 설계:** 모델·과업·페르소나·중요도 산정·메모리 상한·예산을 고정하고, 먼저 성찰·계획 검토 실행 빈도만 비교한다. 그다음 실행 주기를 고정해 검색 정책을 비교한다. 첫 단계에서 선택한 설정을 두 번째 평가에 사용하면 개발셋에서 선택하고 별도 평가셋에서 확인한다.
2. **생성에서 소비까지의 경로 분석:** 예약 → 시작 → 완료 → 유효성 판정 → 다음 의사결정 입력 포함을 연결한다. 호출을 늘렸는데 유효 입력에 거의 도달하지 않는 조건, 오래돼 폐기되는 조건, 성공 증가 없이 비용만 늘어나는 조건을 분석한다. 입력에 포함됐다는 사실을 모델의 실제 의존·인과 효과로 해석하지 않는다.
3. **웹 UX 맥락의 여러 평가 축:** 독립 과업 성공·반복 행동·페르소나 제약 준수·시간·요청/토큰/비용을 각각 보고한다. 성공률과 비용의 상충관계, 제약 준수의 손실 여부를 함께 분석한다. 대시보드·근거·검토 이력·내보내기는 이 평가를 재현하고 검토하기 위한 구현 기여다.

새 실행 정책을 제안하려면 고정 주기 외에 오류·정체·화면 변화 등의 발동 규칙을 명세하고, 동일 조건의 고정 정책과 비교해야 한다. 파일럿 결과를 본 뒤 그 규칙을 평가셋에 맞추면 탐색과 확증을 구분해 보고한다. 일정상 구현·평가가 어려우면 고정 정책의 비교 연구로 범위를 낮춘다.

## 실험 설계에서 먼저 결정할 점

| 결정할 점 | 권장 명세 |
|---|---|
| Slow-off의 범위 | 중요도 산정은 모든 조건에서 동일하게 두고 성찰·계획 검토만 끄는 안을 우선 검토한다. 중요도까지 끄면 검색 품질·비용·제거 규칙이 함께 바뀐다. |
| 성찰과 계획 검토 | 둘을 함께 켜고 끄면 묶음의 효과만 알 수 있다. 기능별 기여가 논문 주장이라면 별도의 제거 조건이 필요하다. |
| 빈도의 단위 | 행동 시도 수·성공 행동 수·경과 시간 중 하나를 명세한다. 예약 빈도, 실제 시작·완료 빈도, 유효 입력 포함 빈도를 별도로 기록한다. Fast 3단계 호출을 `3:1` 같은 실행 비율로 바로 바꾸지 않는다. |
| 중복·지연 처리 | 동시 작업 수, 새 작업이 기존 작업을 대체하는지, 대기열 길이, 취소 시점, 종료 후 완료를 기다릴지 정한다. 같은 주기도 이 규칙에 따라 실효 빈도와 비용이 달라진다. |
| 유효성의 범위 | 현재 계획에 대한 검토와 장기 성찰을 구분한다. 화면 ID가 달라졌다는 이유만으로 모든 성찰을 폐기하면 유용한 결과까지 없어질 수 있다. 어떤 입력·계획 변경이 해당 산출물을 무효화하는지 명시한다. |
| 실제 입력 포함 | 검색 결과 ID, 실제 프롬프트에 넣은 ID·순서, 생성 기록 ID·기준 시각·계획 버전을 연결한다. 완료됐지만 한 번도 전달되지 않은 작업과 실제로 전달된 작업을 구분한다. |
| 공정한 비용 비교 | 같은 양의 전체 요청·토큰·시간·행동 상한을 적용하고, 중요도·repair·fallback·embedding·성찰·취소/폐기 작업도 집계한다. 누락 비용은 0으로 바꾸지 않는다. |
| 시간과 검색 | 최신성의 시간 기준을 고정한다. 잦은 성찰 때문에 wall time이 늘면 같은 행동 순번에서도 기억 최신성 점수가 달라질 수 있으므로, 지연에 따른 매개 효과를 기록한다. |

이는 팀의 설계 제안이며 논문에 적힌 정답 설정이나 확정 회의 결정이 아니다. [기존 메모리 실험 초안](2026-10-15-memory-policy-experiment.md)의 정규화·top-k·점수 도착·미산정·개발/평가 분리 규칙과 함께 적용한다.

## 데이터와 결과에 따른 주장 범위

| 확보한 증거 | 쓸 수 있는 범위 | 아직 쓸 수 없는 주장 |
|---|---|---|
| 합성 fixture·Mock | 실행·로그·근거·내보내기 계약의 검증 | 실제 LLM 정책 개선, 사람 행동 재현 |
| 통제 과업의 실제 모델 rollout | 명시한 모델·과업·예산 범위의 정책별 차이 | 일반적인 UX 품질 향상, 인간 참가자 대체 |
| 페르소나 제약 주석 | 예산·선호·기술 숙련 등의 명시 제약 준수 | 실제 인구집단 행동·판단과의 일치 |
| 이후 기업체의 과업·UX 보고서 | 사용 조건 확인 뒤 문제 후보·실무 판단과의 대응 분석 | 사람 행동 로그가 없는 자료로 행동 유사성 증명 |
| 이후 실제 사람의 동일 과업 기록 | 범위·동의·비교 기준을 정한 뒤 행동·판단 차이 분석 | 표본·사이트 밖 전체 사용자에 대한 보편적 재현 |

기업체 수령 수량과 자료 정의는 수령 후 별도로 기입한다. 공개 데이터셋을 사용한다면 원문 데이터 카드·라이선스·과업과의 적합성·중복/평가 누출을 확인한다. 공개 데이터 활용 계획과 기업체 수령 내역은 합치지 않는다.

## 제출용 짧은 표현

본 연구는 UXAgent 등 선행 연구의 페르소나 및 비동기 두 루프 구조를 바탕으로, 웹 과업에서 성찰·계획 검토의 실행 정책과 메모리 검색 정책을 비교하는 것을 목표로 한다. 특히 지연된 생성 결과의 출처·유효성·실제 의사결정 입력 포함 여부를 추적하여, 과업 수행과 페르소나 제약 준수 및 시간·비용의 상충관계를 분석하고자 한다. 이는 현재 제안하는 실증적 기여이며, 새로운 알고리즘의 최초성이나 인간 행동 재현성이 검증된 상태는 아니다.
