## 2026-10-21 protected task/control data cannot fit

- 증상:20261021T031048-4faff60e가 첫decision의 문맥 준비 단계에서 막혀0행동/33.91초/model_error로 끝났다. 화면 본문을 이미 요약했지만 보호 컨트롤과 긴 행동 지침이 남았다.

## 2026-10-20 팝업 누락·실패 오인·설문과 실제 실행 불일치

- 해결: 아이콘 컨트롤·dialog 경계를 보존하고 압축에 팝업과 조작 대상을 넣는다. 실제 첫 행동 결과를 feedback·plan·decision에 전달하며 실패한 단계는 유지/복구하도록 지시한다. 전체 설문 기억에 generated 상태를 표시하고 실제 steps를 별도로 제공해 오류 수를 대조한다. 모든 질문의 reason을 명시적으로 요구하고 시도하지 않은 단계를 실패로 묘사하지 않게 한다. 등록된 데카트론 과업만 독립 부분 평가를 연결한다. 인식용 중복 control XML은 값/이름/역할을 보존해 간략화한다.
- 함께 확인할 회귀: 빈 아이콘 닫기·모달 사라짐·원래 semantic ID 실행, 메뉴/검색·작은 화면·다른 제공자, 실제 첫 제안과 실패 결과 전달·미실행 결과unknown·계획 비진행, 설문 전체 trace/비밀값/오류 수 누락·불일치/이전 답변 보존, 다른 목표·사이트에 평가 미적용, 문구·가격·현재 값·행동 매핑 보존과 호출 수.
- 실제 검증: 각 단계의 실패 테스트를 먼저 확인했다. 팝업/관찰/Fast33건, feedback/runner/Brain46건, 설문17건, 평가/GPU37건, 최종 관련64건이 각각 통과했다. 실제 Close를 클릭해 팝업을 닫은 뒤 러닝 클릭도 성공했다. Qwen 재생은 실패 클릭을 실패로 해석했고 설문 오류3건과 검색 미제출을 구분했다. 동일 저장 화면의 인식 호출은3→1, 실제 측정8.60→3.72초였다. 서버 부하가 같은 비교는 아니며 전체 과업 성능으로 일반화하지 않는다. 전체 회귀/실제 재실행 결과는 verification을 따른다.

## 2026-10-20 열린 메뉴 반복·GPU 대기·관찰 타입 재호출

- 해결: 현재 메뉴 경로·하위 항목·모두 보기 링크를 계획/행동에 전달했다. 제공자별 단일 큐에서 Fast를 우선하되3회 후 대기 Slow를 처리한다. 큐에서 취소된 요청은 보내지 않고 이미 보낸 요청은 완료까지 슬롯을 유지한다. GPU 조각의 단일 문자열은 내용 그대로 배열로 감싸고 feedback은 짧게 생성하도록 지시한다. 기본 실행 시간은 늘리지 않는다.
- 함께 확인할 회귀: 메뉴 ID 실행/열린 하위 경로/다른 사이트, 큐 단일 실행·Fast 우선·Slow 기아 방지·대기/실행 취소, 원본 응답 로그 보존·다른 타입과 잘린 내부 JSON 거부, 모든 상품/가격/입력값 보존.
- 실제 검증: Qwen+실제 브라우저에서 러닝화모두 보기로 카테고리 이동 성공. 실제3요청 순서가 Fast 우선 정책과 일치했다. 같은 feedback 실패 입력 재생은1회5.18초/70토큰으로 통과했고 최종 관련89건이 통과했다.300초 자율 실행은5/5행동 성공이지만 과업failure였다. 종료된 원격 추론을 선점하거나 여러 클라이언트의 경합까지 없앤 것은 아니며 상세 결과는 verification을 따른다.

## 2026-10-20 GPU 터널 단절이 모델 JSON 오류로 표시됨

- 증상: `model_output_error: provider_transient:ConnectionRefusedError`. 대시보드는 연결됨으로 보이지만 Qwen 요청이 실패했다.
- 원인: 소유 Slurm 작업19375는 RUNNING인데 SSH master와 로컬8001/8002 listener가 없었다. 대시보드는 과거 연결 검증만 신뢰했다. Fast는 전송 재시도 소진 뒤에도 JSON 수정 요청을 보내 원인을 모델 출력 오류로 바꿨다.
- 해결: 5초 health 감시와 실행 전 검사를 추가한다. 소유 작업·RUNNING·지정 노드를 확인한 뒤 사라진 SSH 터널을 복구한다. 실패하면 연결 표시를 해제하고 실행 파일/브라우저 생성 전에 막는다. 전송 오류는 JSON 수정으로 보내지 않고 GPU 연결 실패는 model_connection_error로 남긴다. 종료 시 로그인 master가 없어졌으면 재인증해 소유 작업을 반환한다.
- 함께 확인할 회귀: 정상 JSON 교정·거부, GPU4회/다른 제공자2회 재시도 한도, 실제 모델명, false 연결 표시, 실행 전 거부, 만료/타인 작업 미재사용, 반환 실패 시 기록 유지, shutdown의 감시 thread 종료.
- 실제 검증: 수정 전 새 회귀7건 실패, 수정 후 관련96건·전체557건 통과. 뒤이은 실제 장애 주입에서 TCP TIME_WAIT에 의한 추가 지연을 발견해 아래 후속을 적용했다. 최종 결과는 verification을 따른다.

## 2026-10-20 터널 종료 직후 TIME_WAIT로 복구 지연

- 증상: 실제 SSH 중단 후 연결 재시도14초가 소진되고, 시간이 지난 뒤에야 터널이 복구됐다.
- 원인: 단순 bind 사전 검사가 listener가 종료된 포트의 TIME_WAIT도 사용 중으로 판정했다. 실제 TCP listener를 닫은 직후 같은 코드가 실패하는 회귀 테스트로 재현했다.
- 해결: 시작 포트 검사는 SO_REUSEADDR를 사용하고, 같은 소유 세션의 터널 복구에서는 중복 bind 검사를 생략한다. OpenSSH의 ExitOnForwardFailure로 실제 포트 충돌을 계속 거부한다. 살아 있는 listener의 거부는 유지한다.
- 함께 확인할 회귀: 사용 중인 포트 거부, 닫힌 연결 허용, 소유 할당을 재사용한 login/compute master 복구, 채팅·임베딩·유효 JSON 회복. 검증용 대량 mock 로그는 대시보드가 재귀 조회하는 runs 밖의 임시 경로에 둔다.
- 실제 검증: TIME_WAIT 회귀는 수정 전 실패했고 수정 후 GPU·키·키체인 관련48개가 통과했다. 실제 장애 주입 및 최종 전체 검사 결과는 verification에 기록한다. 운영 기준은 [모델·JSON 매뉴얼](model-json-operations.md)을 따른다.

- 증상: Qwen이 `type` action을 반환했지만 필수 `description`이 빠져 `UActions` 검증에서 중단됐다. 같은 응답의 첫 문법 오류 수정 후에도 이 필드가 계속 누락됐다. 실행 시도 수는 0이므로 Playwright 오류가 아니다.
- 원인: 기존 수정 요청은 검증 오류 문장만 주고, 완성해야 할 JSON 구조나 누락 필드의 위치를 보여주지 않았다.
- 해결: Fast 재요청은 response model에서 필수 JSON 템플릿을 생성한다. 파싱 가능한 응답에서는 action/target/text/enter 등 기존 유효 값을 유지하고 빠진 `description`을 빈 문자열로 추가해 모델이 채우도록 한다. 원본은 대화와 호출 로그에 유지한다. 재시도는 한 번으로 제한한다.
- 함께 확인할 회귀: description 누락, 문법 오류 뒤 재시도, plan 등 다른 response model, 원본 값 보존, 수정 후에도 invalid인 응답의 fail-closed 처리, 요청/usage 로그.
- 실제 검증 결과: U Fast·prompt guard·target selection **46 passed in 4.64s**. 실제 GPU Qwen 재요청은 아직 하지 않았다.
