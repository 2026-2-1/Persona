# D-01 사람 판정 입력·저장 화면

담당: 곽태훈 (@taehun0208). 작업 [#32](https://github.com/2026-2-1/Persona/issues/32), 기존 [#7](https://github.com/2026-2-1/Persona/issues/7)·[#8](https://github.com/2026-2-1/Persona/issues/8), 선행 [C PR #30](https://github.com/2026-2-1/Persona/pull/30).

## 사용 흐름

완료한 실행을 선택하고 개선 보드에서 근거를 확인한다. 카드 아래 사람 검토에 검토자 별칭·판정·메모를 입력하고 **판정 저장**을 누른다. 판정은 유효 후보/무효 후보/판단 보류/도구 오류/환경 오류다. C의 `POST /api/reviews/<run_id>`에 기존 카드 ID·내용 버전을 전달하며 별도의 서버 저장 코드를 추가하지 않는다.

서버가 저장을 확인한 경우에만 완료 문구와 최신 판정을 보여준다. 새로고침 후 저장된 판정은 실행 상세에서 다시 읽는다. 사람의 후보 판정은 독립 과업 성공이나 확정 UX 결함을 의미하지 않으며 별칭은 인증된 신원이 아니다.

## 오류와 입력 보존

- 저장 중 입력·버튼을 잠가 중복 제출을 막는다. 미저장 입력은 해당 페이지 메모리에만 있으며 브라우저 영구 저장소에 기록하지 않는다.
- 400은 입력 확인, 404/409는 실행·카드 근거 재조회, 500은 서버/이력 상태 확인으로 안내한다. 실패 시 작성 중인 내용을 유지한다.
- 404/409 뒤에는 저장을 잠그고 **근거 다시 확인**으로 실행 상세를 다시 읽는다. 새 버전에는 이전 입력을 자동 적용하지 않는다.
- 응답을 받지 못한 경우 저장 여부를 확정하지 않는다. 중복 저장 전에 최신 판정과 서버 상태를 확인한다.
- 같은 카드의 자동 갱신은 폼을 교체하지 않는다. 실행·카드·버전으로 입력을 구분한다. 페이지를 닫거나 새로고침하면 미저장 입력은 사라진다.

## D-02 초안 보존과 지연 응답 (#33)

D-01 PR #37의 59f67dc 기반 `feat/33-review-draft-retention`에서 보완했다. 실행·카드·근거 버전별 페이지 메모리 초안을 재사용하며 영구 브라우저 저장은 추가하지 않는다. 자동 갱신과 실행 왕복은 입력을 유지하지만 전체 페이지 새로고침/탭 종료는 미저장 입력을 지운다. 저장된 판정은 서버에 남는다.

늦게 도착한 조회가 저장 완료 상태를 되돌리거나 실행 왕복 전 화면을 다시 표시하지 않도록 조회 시점의 변경 번호를 확인한다. 선택 변경·서버 저장 확인·명시적 근거 재조회가 기존 조회를 무효화한다. 진행 중 조회가 있을 때 요청된 갱신은 끝난 직후 이어서 수행한다. 카드가 갱신되어도 메모와 별칭 입력의 포커스·선택 구간을 복원한다. 새 근거 버전에 옛 초안을 자동 적용하지 않는다.

검증은 두 실행에 같은 카드 ID를 넣어 교차 오염을 확인한다. 추가 브라우저 사례는 자동 갱신·두 카드/두 실행 왕복·지연 조회·지연 저장 성공/실패·재시도·외부 판정 갱신 중 텍스트 선택·진행 중 조회에서 같은 실행 재선택이다. 실제 화면에서도 서로 다른 합성 실행에 미저장 메모를 넣고 왕복했다.

D-02 PR은 #37 브랜치를 대상으로 변경만 검토한다. 선행 #30 → #37을 prototype에 통합한 후 D-02의 base를 prototype으로 변경하고 CI·팀원 리뷰를 확인한다. 선행 작업 브랜치로 직접 병합하지 않는다.

## D-03 검토 이력·실행 출처 (#34)

D-02 PR #38의 f196579를 기반으로 작업한다. 현재 카드의 `review_history`와 실행 전체 `reviews`를 재사용해 현재/이전 근거 버전의 검토자 별칭·판정·메모·서버 시각을 최신 저장순으로 표시한다. 이전 버전 판정은 현재 카드에 적용하지 않는다. 저장 응답을 받은 이력만 즉시 추가하며 동일 버전의 펼침 상태와 D-02 초안을 갱신 시 보존한다.

실행 기록과 개선 보드에 `execution_mode`(AI/scripted/미확인)와 `source_kind`(합성/설정된 실제 사이트/미확인)를 나란히 표시한다. provider=mock은 Mock 데모로 구분한다. 모델명·URL만으로 누락된 실행 방식이나 출처를 추정하지 않는다. 실제 사이트 실행도 실제 사람 행동의 근거가 아니며 별칭은 인증 신원이나 독립 합의가 아니다.

관련 후속 [#47](https://github.com/2026-2-1/Persona/issues/47)의 Brain 단계·Slow 작업·메모리 UI는 별도 범위다. AI `plan_review`와 여기의 사람 검토를 합치지 않는다. 새 Brain 필드가 없는 기존 실행을 지원한다. 선행 #30 → #37 → #38 통합 후 prototype에서 재검증하며 선행 브랜치로 직접 병합하지 않는다.
