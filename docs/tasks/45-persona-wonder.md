# [phase:1] Persona 기반 1% Wonder

GitHub: [#45](https://github.com/2026-2-1/Persona/issues/45)

## 범위와 결정

- 실행된 reflection 또는 plan_review 작업마다 독립적으로 한 번, 1% 확률을 추첨한다. 동일 작업의 제공자 재시도는 다시 추첨하지 않는다.
- 기본 활성화한다. `enable_wonder=false`로 끌 수 있고 `wonder_seed`로 추첨을 재현할 수 있다.
- 당첨 시 별도 비동기 모델 요청을 만든다. 입력은 persona의 배경·디지털 친숙도·선호·제약뿐이며 `intent`, 현재 과업·화면·기억·평가 정답은 제외한다. 일반 AI 조건에는 공통 제약만 전달한다.
- 생성된 생각은 가정으로 표시한다. 실제 사용자 기억·확정 선호·성공 근거로 해석하지 않는다. 1%는 사람 행동 확률이 아니라 시작된 Slow 작업당 실험 추첨률이다.
- 추첨 seed·부모 작업 ID·결과, Wonder 작업의 예약·시작·완료·채택·폐기·실패·취소를 기록한다. 공통 요청·토큰 예산을 사용한다.
- 활성 기억이 꽉 찼을 때 과업 기억을 Wonder 때문에 제거하지 않는다. 새 과업 기억이 들어오면 기존 Wonder를 먼저 제거한다. 다음 Fast 단계의 우선 삽입 대상에서도 Wonder를 제외한다.

## 구현 상태

- [x] 시작된 Slow 작업별 추첨과 별도 persona 입력 생성.
- [x] 실행별 seed와 추첨·작업·생성 단계·기억 출처 기록.
- [x] 예산·실패·취소·메모리 상한 처리.
- [x] 대시보드와 Markdown/HTML/JSON 출력에서 생성 가정 표시.
- [x] 당첨·비당첨·재시도·일반 조건·낮은 기억 상한·취소·민감정보 회귀 검사.

## 제한

- seed는 추첨 결과를 재현하지만 비동기 작업 완료 순서까지 고정하지 않는다.
- 생성 문장의 과업 무관성은 프롬프트의 요청이며 별도 의미 판정기로 보증하지 않는다.
- 실제 유료 API와 실제 사람의 행동 확률은 검증하지 않았다.
