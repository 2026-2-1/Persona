# Task 09 — 통합 검증과 실험 기록

상태: mock 통합 검증 완료; live 검증 대기 | 선행: 08 | 단계: 최종 검증

## 목표

“브라우저가 움직인다”, “논문 구조를 구현했다”, “인간 UX를 재현한다”를 서로 다른 검증 대상으로 다룬다. 앞의 두 항목부터 확인하고 세 번째는 별도 연구 과제로 남긴다.

설계 연결: 논문 §5.3–5.4. 아래 검증 기준·표본 수는 프로젝트 제안이다.

## A. 기능 검증 — mock/fixture 우선

| 검증 | 확인할 실패 | 합격 기준 |
|---|---|---|
| 관찰 | 숨김 노출·중복 ID·입력값 누락 | 02의 fixture 기대값 일치 |
| 행동 | stale ID·가린 버튼 강제 클릭 | 실행 전 거부 또는 구조화된 오류 |
| 판단 | 잘못된 JSON·없는 target | 제한 재시도, 임의 클릭 없음 |
| 종료 | 무한 반복·거짓 완료 | 상한 종료, evaluator와 주장 분리 |
| 메모리 | 누락 점수·중복 임베딩 | 정의한 검색·캐시 정책 일치 |
| 비동기 | Slow 응답이 Fast를 정지 | Fast 진행, budget 상한 준수 |
| 배치 | 이전 실행 상태 유출 | context와 fixture 상태 초기화 |
| 인터뷰 | 미래 정보 누출 | 입력 snapshot 경계 준수 |
| 결과 | 잘못된 PNG/단계 연결 | 모든 근거 참조가 실제 파일과 대응 |

각 task에서 이미 통과한 검사를 이유 없이 반복 확대하지 않는다. 통합 시 바뀐 계약과 남은 위험만 다시 확인한다.

## B. 최소 live 확인

1. 05 완료 시 고정 persona 1명 × fixture 과제 1개 × 실행 1회.
2. 전체 구현 후 persona 3명 × 같은 과제 1개 × 각 1회.
3. 차이가 생겼을 때만 같은 persona를 3회 반복해 모델 변동 여부를 살펴본다.

이는 작은 구현 점검이며 통계적 검증이 아니다. 모델 호출 예산을 먼저 설정하고 예산을 초과해 성공 사례만 수집하지 않는다. 실패 run도 보존한다.

## C. 구성 요소 비교 — 필요할 때만

| 조건 | 기억 | Slow | 목적 |
|---|---|---|---|
| A | 최근 6단계 | off | MVP 기준선 |
| B | 검색 기억 | off | 검색 영향 |
| C | 검색 기억 | Reflection on | 성찰 영향 |
| D | 검색 기억 | Reflection + Wonder | Wonder 탐색; 선택 |

같은 persona/task/site 상태/viewport/model/prompt 버전을 사용한다. 한번에 한 요소만 바꾼다. API 모델이 비결정적이면 seed만으로 재현된다고 표현하지 않는다. split Fast 모드는 별도 조건으로 비교한다.

비교 항목은 검증된 성공 수, action attempts, 오류 코드, 반복 행동, LLM 호출·토큰·소요 시간이다. 성공률이 올라가도 인간다운 행동이 개선되었다고 결론내리지 않는다.

## D. 비율과 시간 해석

- 기술 성공률: verified success / 시작된 전체 run. timeout·오류도 분모에 포함한다.
- 판정 가능한 run 성공률: success / (success + failure). unknown 수를 함께 표시한다.
- 분모·제외 기준을 표시하고 서로 다른 성공률을 혼합하지 않는다.
- 모델 응답 속도와 페이지 로딩 속도를 사용자 숙고 시간으로 바꾸지 않는다.
- 같은 URL을 여러 번 방문했다고 무조건 길을 잃은 것으로 분류하지 않는다.
- 여러 persona가 같은 문제를 말해도 독립적인 실제 사용자 증언으로 취급하지 않는다.

## E. 실제 사이트로 옮기는 조건

- fixture에서 관찰·행동·로그 연결이 안정적으로 통과한다.
- 읽기 중심의 짧은 과제를 고른다. 실제 결제·전송이 필요한 과제는 제외한다.
- 수동으로 확인 가능한 성공 기준을 사전에 정한다.
- iframe/canvas/커스텀 컨트롤/로그인/CAPTCHA 때문에 지원되지 않는 구간을 기록한다.
- 긴 페이지가 필요하면 관찰·스크롤 정책을 먼저 선택하고 실험 이름에 명시한다.
- 사이트별 evaluator는 허용한다. executor에 사이트별 정답 클릭 경로를 하드코딩하지 않는다.
