# 비동기 Slow 실행 정책·메모리 검색 정책 실험 계획

작성일: 2026-10-15 KST. 상태: **팀 대화 반영 제안서, 회의 확정 전**. 기업체 데이터는 사용자가 미수령이라고 확인했으며 확보 수량은 0건이다. 아래 조건·수량·일정은 실험 계획이지 수행 결과가 아니다.

## 1. 대화에서 추가된 연구 범위

초기 안건은 활성 기억 64개, Fast/Slow 검색 가중치, 호출 상한이었다. 후속 대화에서는 Slow의 전략 제안, 계획 이후 비동기 검토, 다음 계획 반영, Slow 제거·실행 빈도 비교까지 범위가 넓어졌다.

**연구 질문:** 페르소나 웹 과업에서 비동기 성찰·계획 검토의 실행 빈도와 메모리 검색 정책이 독립 과업 성공, 제약 준수, 반복 행동, 시간·비용에 어떤 영향을 주는가? 특히 지연된 결과가 실제 입력에 전달된 비율과 오래된 결과의 배제 여부를 함께 관찰한다.

가설은 양방향으로 둔다. 성찰이 반복을 줄일 수도 있지만 호출·지연·오래된 전략 때문에 이득이 줄거나 성능이 나빠질 수도 있다. 비슷한 결과가 나와도 작은 표본의 차이 미검출을 효과 없음으로 단정하지 않는다. 과업 수행 개선과 인간 행동 재현은 별도 연구 질문이다.

## 3. 용어와 비교 단위

- **중요도 산정:** 기억을 1~10점으로 평가하는 작업. 고수준 성찰·계획 검토와 따로 센다.
- **성찰:** 기억에서 전략·인사이트를 생성하는 작업. 실제 관찰 사실이 아니다.
- **계획 검토:** 특정 plan ID/버전에 대한 일관성 검토·수정 제안. 행동 허가나 과업 성공 판정이 아니다.
- **Fast 판단 차례:** 현재 관찰에서 인식→계획→행동 결정을 수행하는 한 차례. 모델 종료 선언으로 실제 행동이 없을 수도 있다.
- **실행 빈도:** 예약 대상 Fast 차례의 간격. Fast 3개 생성 단계와 Slow의 수를 단순히 3:1로 부르지 않는다. 실제 예약·시작·완료 횟수와 행동 횟수를 따로 보고한다.
- **실제 입력 소비:** 생성 결과 또는 그 결과를 담은 기억 ID가 이후 모델 요청 입력에 포함됐음. 모델이 그 결과 때문에 행동했다는 인과 증명은 아니다.

## 4. 1차 실험: 성찰·계획 검토의 실행 빈도

주요 조작은 고수준 Slow의 예약 빈도이며 검색 가중치는 모든 조건에서 동일하게 고정한다. 중요도 산정은 모든 조건에서 동일하게 실행한다. 이 독립 제어는 최신 강제 활성/점수화 결합 경로에 **아직 추가해야 하는 연구용 확장**이다. 설정 파일만 바꿔 이미 실행 가능한 실험이라고 보지 않는다.

| 조건 ID | 성찰·계획 검토 예약 | 비교 의미 |
|---|---|---|
| `review-off-v1` | 둘 다 예약하지 않음 | 고수준 검토가 없는 기준선. 전체 Slow 기능 제거 또는 순수 Fast-only라고 부르지 않음 |
| `review-every-5-v1` | Fast 판단 차례 i가 5의 배수일 때 예약 | 드문 검토의 이득·비용 |
| `review-every-1-v1` | 매 Fast 판단 차례 예약 | 빈번한 검토의 이득·지연·취소 |

예약 대상 차례에서는 perception 저장 직후 성찰, plan 저장 직후 계획 검토를 각각 예약한다. Fast는 기다리지 않는다. 빈도는 두 작업에 같이 적용하므로 1차 결과는 **성찰+계획 검토 묶음의 효과**다. 두 작업 각각의 효과를 주장하려면 후속으로 reflection-only/plan-review-only 조건을 추가한다.

주 비교는 `review-off-v1` 대 `review-every-5-v1`, 빈도 비교는 every-5 대 every-1로 사전 지정하는 안이다. 초기 실험에서는 오류 발생 시 추가 예약을 끄고 Wonder도 끈다. 오류 발동을 채택하면 모든 조건의 규칙과 off 조건의 예외를 명시하고 별도 정책으로 버전을 바꾼다.

정말로 모든 Slow 작업을 제거하려면 중요도 산정까지 끈 별도 조건이 필요하다. 이 조건은 점수의 존재도 함께 달라지므로 1차 실험과 다른 결합 효과로 해석한다.

## 5. 2차 실험: 주기 고정 후 메모리 검색 정책

1차 개발 파일럿에서 선택한 주기를 고정한다. 1차 최종 평가 결과를 보고 가장 좋은 주기를 골랐다면 탐색 선택으로 표시하고 새 평가 과업에서 확인한다.

가중치 순서는 **(중요도 I, 관련성 Q, 최신성 R)** 이다. 다음 계수는 프로젝트 제안이며 논문이 정한 숫자가 아니다. 최신 #77의 Slow 최신성 우선 `(0.2,0.2,0.6)`와도 다르다. 예산이 허용하면 최신 구현 정책을 네 번째 기준 조건으로 추가하거나, 아래 equal 조건 대신 사용할지 사전 확정하고 세션 수를 다시 계산한다.

| 정책 ID | Fast | Slow | 의미 |
|---|---|---|---|
| `equal-v1` | (1/3, 1/3, 1/3) | (1/3, 1/3, 1/3) | 동일 가중치 기준선 |
| `fast-recent-slow-relevant-v1` | (0.2, 0.3, 0.5) | (0.2, 0.5, 0.3) | 논문에서 방향을 얻은 최신성/관련성 강조 |
| `fast-recent-slow-important-v1` | (0.2, 0.3, 0.5) | (0.5, 0.2, 0.3) | 팀의 Slow 중요도 우선 가설 |

주 비교는 두 번째와 세 번째 정책으로 Slow의 I/Q 배분만 바꾼다. equal 대 두 번째는 Fast와 Slow가 함께 바뀌는 전체 정책 비교다. Fast만의 효과로 해석하지 않는다. 종류 가중치·동점·미산정 제외·정규화·중복 제거는 조건 간 동일하게 둔다.

활성 상한 64, 최근 10개 보호, 검색 반환 상한 8, 모델에 실제 전달하는 개수는 구분한다. 초기 생성 provider 하나를 쓰고 실효 top-k 6을 제안하되 Slow 입력 연결 뒤 확정한다. Jev 경로의 4개와 생성 경로의 6개를 같은 조건에 섞지 않는다. 중요도 산정 요청은 검색 정책으로 입력이 잘리지 않도록 별도 고정한다. 상세 근거·replay 규칙은 [메모리 정책 상세](2026-10-15-memory-policy-experiment.md)를 따른다.

## 6. 비동기 실행·채택 계약 제안

다음은 구현 완료가 아닌 회의에서 확정할 정책이다.

1. 최신 구현은 단일 Slow worker와 상한 없는 대기열이다. 초기 비교에서는 같은 worker/대기 규칙을 모든 조건에 유지하되 중요도 산정의 공통 예약을 별도로 마련한다. 기존 제안의 유형별 동시 1개/대기 1개·새 예약 교체는 별도 정책 변경이므로 자동 채택하지 않는다. 안전한 상한을 합의하면 모든 조건에 동일 적용하고 버전을 동결한다.
2. 시작 시 기억 값·점수·snapshot 기준 순번·observation ID·plan ID/버전을 고정한다. 나중 도착한 점수를 과거 입력에 소급 적용하지 않는다.
3. 생성 결과를 완료했다고 자동으로 높은 가중치를 주지 않는다. 기억 검색 정책과 결과 채택 기준을 각각 고정한다.
4. 완료 결과의 출처·계획 버전과 현재 상황을 확인한다. 최신 코드의 plan_review는 동일 계획/관찰의 decision 경계에서만 채택된다. 이를 유지하는 실험과 다음 새 계획의 참고로 확장하는 실험을 섞지 않는다. 오래된 요소 ID·클릭 명령을 재사용하지 않으며 일반 성찰은 화면 ID 변경만으로 전부 폐기하지 않는다. 유효기간/재확인 규칙을 실험 전에 명세한다.
5. 모델 입력이 만들어진 뒤 도착한 결과는 그 입력을 바꾸지 않는다. 다음 입력에 포함됐는지를 별도 기록한다.
6. 종료 시 대기/취소 정책과 유예시간을 공통으로 고정한다. 본문 시간에는 실제 종료까지 포함한다. 끝난 뒤 결과를 생성해서 이미 끝난 행동에 사용됐다고 기록하지 않는다.

필수 기록: condition/policy ID, Fast 차례 번호, 작업 kind·시각, 생성/snapshot/계획/관찰 출처, 검색 순위/ID, 실제 전달 ID, 유효 판정·제외 사유, 소비된 요청 ID, usage completeness·종료 사유. 최신 스키마는 기본 6상태에 adopted/discarded를 더한 8상태이며 새 필드를 전부 재발명하지 않는다. adopted는 기억/경계 후보로의 채택이므로 실제 단계 `source_memory_ids`와 생성 ID를 연결해야 입력 포함이 확인된다. 연구 조건·모델 요청 연결 등 누락 필드만 계약 확장한다.

## 7. 데이터·과업·예산 고정

기업체 자료는 미수령이다. 우선 로컬 합성 과업과 무료 fake/mock으로 계약을 검증하고, 실제 모델 실험은 별도 예산 안에서 새 결정을 실행한다. 공개 사이트 부분 성공, 합성 결함, 기업체 데이터, 사람 자료를 별도 출처로 구분한다.

- 동일 과업·페르소나·구매 제약·fixture commit·viewport·초기 세션 상태·독립 평가기를 대응 블록으로 묶는다. 모델/provider/temperature/출력 상한·fallback·embedding·반감기를 고정한다.
- 최신성의 시간 기준도 고정한다. 잦은 성찰이 wall time을 늘리면 같은 행동 순번에서도 기억 점수가 달라질 수 있다. 이를 지연에 따른 매개 효과로 기록하고, 고정 snapshot의 순위 분석과 실제 rollout 결과를 구분한다.
- 매 실행 브라우저와 메모리를 초기화하고, 정책 순서는 블록 안에서 균형 있게 섞어 seed와 실제 순서를 남긴다. seed가 모델 응답의 결정성을 보장하지는 않는다.
- 개발 과업과 최종 평가 과업을 분리한다. 평가셋을 보고 주기·가중치·프롬프트를 조정하지 않는다. 같은 사이트 템플릿 변형은 독립 사이트 일반화 근거로 쓰지 않는다.
- 요청 상한 `B_request`, 토큰 상한 `B_token`, 총 지출 상한·가격 기준일을 파일럿 후 확정한다. 미정인 동안 유료 본 실험을 시작하지 않는다. 공통 단계/시간 상한의 시작안은 현재 기본 30단계/300초이며 파일럿에서 적절성을 확인한다.
- 중요도·성찰·검토·embedding·형식 복구·fallback 요청을 예산에 모두 포함한다. preview의 Fast 3회+중요도 4회 예상치를 최신 실행기에 그대로 쓰지 않는다. 새 PR #76/#77 작성자의 6행동 Mock은 58요청이며 성찰 생성 기억까지 점수화한다. 실제 모듈별 호출·중단·취소를 다시 측정한다.
- 예상 지출은 파일럿의 조건별 세션 비용 × 예정 세션 수와 재시도 한도로 계산한다. 가격/usage 누락은 0으로 채우지 않는다. 예산 상한에 걸린 비율도 결과로 보고한다.

## 8. 규모와 단계별 통과 기준

| 단계 | 수량 제안 | 산출물·진입 조건 |
|---|---:|---|
| 무료 계약 검증 | 고정 건수 대신 경계 사례 완료 | 늦은 결과·취소·오래된 plan·제거 기억·예산 소진·실제 소비 ID 회귀 |
| 1차 개발 파일럿 | 1과업 × 2페르소나 × 3빈도 × 3반복 = 18세션 | 사용량·대기·지표 정의 점검, 정책/예산 동결 |
| 1차 최종 평가 | 새로운 3과업 변형 × 2페르소나 × 3빈도 × 5반복 = 90세션 | 빈도 효과의 제한된 평가. 충분한 검정력 보장은 아님 |
| 2차 개발 파일럿 | 1개 개발 과업 × 2페르소나 × 3검색 정책 × 3반복 = 18세션 | 실제 Slow 검색이 달라지는지·소비·비용 확인 |
| 2차 최종 평가 | 별도로 보류한 3과업 변형 × 2페르소나 × 3정책 × 5반복 = 90세션 | 검색 정책 평가, 과업 ID와 분리 기준 사전 등록 |

1차만 수행하면 제안 총량은 108세션, 두 단계 전부면 216세션이다. 확보한 데이터 수나 참가자 수가 아니다. 비용/일정이 부족하면 18세션 파일럿까지만 하고 예비 연구로 보고한다. 평가 과업은 처음부터 분리해 준비하며, 소규모 반복 실행을 독립 인간 사용자 수로 세지 않는다. 기존 compare의 1~3반복 제한과 다른 연구 실행 경로가 필요하다.

## 9. 지표와 해석

| 구분 | 지표·분모 | 해석 |
|---|---|---|
| 주 지표 | 독립 성공 / 사전 등록 세션 | 실패·unknown·오류·중단·미실행도 공개, 분모 유지 |
| 사용자 조건 | 명시적 구매/과업 제약별 pass/fail/unknown | 인위적 persona 제약 준수이며 인간 유사성은 아님 |
| 행동 | 같은 상태·행동의 불필요 반복, 시도 행동 수 | 반복 규칙을 파일럿에서 동결, 도구 오류와 구분 |
| 시간·비용 | wall time, 모듈별 요청/실측 토큰/비용, 예산 중단 | 성공 세션만의 값과 전체 분포·측정 대상 수를 함께 표시 |
| 비동기 | kind별 예약/시작/완료/생략/실패/취소 수, 완료율 | 완료 수 / 예약 수. 아직 진행 중인 실행은 최종율과 구분 |
| 실제 소비 | 이후 입력에 들어간 결과 수 / 완료 결과 수 | 입력 ID로 확인, 소비 기회 없이 종료된 수 별도 보고 |
| 지연·유효성 | 생성~첫 소비 시간, 오래된 결과 제외 수/검사 수 | 미소비는 시간 0으로 두지 않고 미소비로 보고 |
| 출처 | 생성→기억→입력→행동의 연결 확보율·누락 | 연결이 있어도 행동 원인의 인과 설명은 아님 |

완료 후 소비율은 고유 결과 ID 기준으로 세고 같은 결과의 여러 입력 사용을 중복 합산하지 않는다. 예약률과 완료율이 낮으면 설정 빈도와 실제 노출이 다름을 함께 설명한다. 일반/페르소나 비교, scripted 점검, 인간 세션을 이 실험의 같은 분모로 합치지 않는다.

최신 로그는 completed 뒤 adopted/discarded가 올 수 있다. 완료 작업 수는 task ID별 전체 사건에 completed가 있는지로 세며 마지막 상태만 보고 누락하지 않는다. adopted 사건과 실제 입력 포함률은 별도다.

조건별 원시 세션표, 대응 블록 차이, 불확실성 구간과 시간/비용 분포를 보고한다. 분석 방법·재시도/제외 기준을 동결하고, 주 비교와 탐색 비교를 구분한다. 차이를 확인하지 못했다면 표본·과업·비용 조건과 함께 보고한다.
