## 먼저 공유할 사실

- 사용자가 기업체 데이터 **미수령, 확보 수량 0건**이라고 확인했다. 아래 자료 요청과 목표 수량은 협의안이다.
- 현재 preview는 A Fast 단계/메모리 생성과 D 화면/출력의 통합 검증본이다. prototype 병합·전체 Slow 조율·실제 모델 성능 평가 완료를 뜻하지 않는다.
- 실제 Mock 기록 42개는 Fast 18개+중요도 24개다. 고수준 성찰/계획 검토가 작동한 증거가 아니다.
- 현재 Slow 설정을 꺼도 중요도 산정은 수행된다. 중요도/성찰/계획 검토를 분리해서 조건 이름을 정해야 한다.
- 어제 메모리 정책 초안은 Slow 주기를 고정했다. 대화 후반의 off/빈도 비교를 새 [상위 실험 계획](../research/2026-10-15-slow-loop-experiment-plan.md)에 추가했다.
- 두 루프·비동기 성찰·I/Q/R 검색 자체는 선행 연구다. 신규성은 검증 전이며 최초/인간 대체를 주장하지 않는다.

가중치가 임시 값이라는 사실과 구현 오류는 구분한다. 확인된 실패 재현·계약 누락·실제 입력 불일치를 근거로 수정 범위를 정한다. 작은 표본에서 차이가 보이지 않더라도 System 2가 일반적으로 불필요하다고 결론 내리지 않는다.

## 멘토에게 프로토타입을 보여준 뒤 확인할 질문

먼저 정상/실패 실행, 근거 화면, AI 생성과 사람 검토 구분, 실제 내보내기 예시를 보여드린다. 이후 아래 중 제공 가능한 범위를 질문한다. 이 문서는 실제 요청/발송 기록이 아니다.

1. 실제 서비스의 대표 과업과 성공/실패 기준을 받을 수 있는가? 초기 협의 목표는 과업 3~5종이다.
2. 익명화된 사용성 테스트/행동 세션 5~10건 또는 기존 검토 결과를 받을 수 있는가? 같은 참여자의 여러 세션인지 구분 가능한가?
3. 전문가가 검토한 문제 목록 10~20건을 과업·화면·근거와 연결해 받을 수 있는가? 목록이 알려진 일부 사례인지 포괄 목록인지 확인한다.
4. 공개 가능한 화면·재현용 테스트 환경·가명 사용자 유형 설명이 있는가? 실제 고객 개인정보가 없는 대체본을 받을 수 있는가?
5. 자료의 제공 목적, 학습/평가 가능 여부, 논문/발표/공개 저장소 사용 범위와 보관·삭제 조건은 무엇인가?
6. 실무에서는 어떤 출력과 비교 지표가 유용하며, 사람이 확인해야 할 오탐·누락 사례는 무엇인가?

목표 수량은 요청 협의용이다. 확보 약속이나 논문에 충분한 표본이라는 의미가 아니다. 실제 자료의 단위·수량·권한을 확인한 뒤 제출 초안을 수정한다.
