# Task 08 — 결과 검토, 모의 설문, 시점별 인터뷰

상태: 구현 및 artifact 생성 검증 완료 | 선행: 07 | 단계: 논문 구조 확장

## 목표

로그를 사람이 검토할 수 있게 만들고, 에이전트의 설명을 해당 실행 근거와 연결한다. 별도 웹 서비스나 대시보드 프레임워크는 만들지 않는다.

설계 연결: 논문 §3.2.3, §3.5. 출력 형식과 아래 질문은 이 프로젝트에서 작성한 것이다.

## 1. 정적 결과 뷰어

`python -m uxagent review --run runs/<run_id>`로 `review.html`을 생성한다. JSON/PNG는 원본 근거로 남기고 상대 경로로 연결한다. 뷰어는 네트워크/API 연결 없이 열린다.

표시 항목:

- 실행 설정·페르소나·모델·프롬프트 버전.
- 종료 사유와 verified success 여부.
- 행동 수, 오류 수, 모델 사용량, 시간 구분.
- 단계별 이전 화면 → 행동 → 실행 결과 → 다음 화면.
- 짧은 관찰 설명·계획·성찰과 출처 단계.
- 문제 후보와 근거 링크.

사이트 HTML이나 LLM 문장을 뷰어에 그대로 HTML로 삽입하지 않는다. escape하여 텍스트로 표시한다. 대상 강조가 필요하면 저장된 bounding box를 원본 PNG 위 별도 overlay로 그린다. 원본 이미지는 수정하지 않는다.

## 2. 사후 설문

기본 질문은 세 개로 시작한다.

1. 과제를 완료했다고 생각하는가? 판단에 사용한 화면은 무엇인가?
2. 진행 중 이해하기 어려웠던 부분은 무엇인가?
3. 다시 이용한다면 바뀌었으면 하는 부분은 무엇인가?

입력은 persona·task·이 실행의 기록만 사용한다. 답변마다 source step ID를 붙이고 근거가 없으면 “기록에서 확인할 수 없음”으로 표현한다. 결과를 실제 사람의 만족도 또는 실제 SUS 점수로 표시하지 않는다. 표준 설문은 필요할 때 별도 버전으로 추가한다.

```json
{
  "question_id": "q2",
  "answer": "가격 필터가 적용되었는지 확인하기 어려웠다.",
  "source_step_ids": [3, 4],
  "data_type": "simulated_self_report"
}
```

설문 API 비용도 기록한다. run이 종료된 뒤 수행하므로 run의 행동 지표를 바꾸지 않고 별도의 postprocess 사용량으로 저장한다.

## 3. 시점별 인터뷰

목표 CLI:

```text
python -m uxagent interview --run runs/<run_id> --at-step 4 --question "이때 어떤 정보를 찾고 있었나요?"
```

`--at-step 4`는 4번 행동 직후의 관찰까지를 뜻한다. action이 없는 종료 제안 단계는 해당 단계의 현재 관찰을 사용한다. 실제 세션을 수정하지 않는 snapshot 질의다.

- [ ] step 4까지 실제 사용 가능했던 메모리만 추린다.
- [ ] 미래 단계의 관찰·성공 결과·요약·설문을 제외한다.
- [ ] source가 과거여도 step 4 이후 생성된 성찰은 제외한다.
- [ ] 그 시점의 persona·task·제약을 사용한다.
- [ ] 답변에 근거 단계와 불확실성을 넣는다.
- [ ] 답변을 별도 `interviews.jsonl`에 저장하고 원래 메모리에 주입하지 않는다.

진행 중 실제 인터뷰 pause/resume은 후속 기능이다. MVP 확장에서는 저장된 시점의 인터뷰로 충분하다.

## 4. UX 문제 후보

규칙 기반으로 반복 행동·반복 오류·포기를 먼저 찾고, 필요할 때 LLM으로 설명을 작성한다.

```json
{
  "issue_id": "issue-01",
  "hypothesis": "필터 적용 상태의 표시가 충분하지 않을 수 있다.",
  "evidence_step_ids": [3, 4, 5],
  "observed_behavior": "같은 필터를 반복해서 조작했다.",
  "alternative_explanations": ["관찰 추출 누락", "모델의 입력 상태 해석 오류"],
  "review_status": "needs_human_review"
}
```

API 429, 브라우저 timeout, 잘못된 요소 추출은 우선 시스템 오류로 분류한다. UX 문제 후보로 포함하려면 화면과 행동 근거를 추가로 검토한다. 사람의 감정이나 UX 문제의 심각도를 모델 확신만으로 수치화하지 않는다.

## 수용 검사

- 임의 step을 클릭하면 맞는 전후 PNG와 행동이 보인다.
- 근거가 없는 step ID를 모델이 반환하면 검증 오류가 난다.
- 미래에만 존재하는 테스트 문구를 인터뷰 입력에 넣지 않았음을 확인한다.
- postprocess 호출을 해도 기존 summary의 행동 수가 변하지 않는다.
- 오류로 종료한 run에서도 뷰어를 만들 수 있다.
- 악성 HTML 문자열이 뷰어에서 코드로 실행되지 않는다.
