# [phase:1] Runner 관찰·Brain·실행·독립 평가 흐름 연결

GitHub: [#44](https://github.com/2026-2-1/Persona/issues/44)

## 범위

- `observe()`가 저장한 JSON/PNG와 관찰 시각, 최신 TargetRegistry를 Brain 입력 전에 확정한다.
- 초기 화면의 성공 조건을 Brain 전에 검사해 조기 종료하지 않는다. 관찰 뒤 perception·plan·decision을 기록한다.
- 행동 제안은 기존 `ActionExecutor`가 최신 observation·탭·허용 origin·capability를 검사한 후 실행한다. 제안·실행 결과·독립 평가 결과를 단계 기록에서 구분한다.
- 실제 행동 뒤 새 관찰과 registry를 발행한 다음 독립 평가한다. `finish`/`give_up`이면 현재 화면을 독립 평가하고 선언과 검증을 따로 기록한다.
- 모델 예산·시간 초과와 모델 오류는 관찰 출처를 가진 미실행 단계로 남긴다. 행동 뒤 관찰 실패는 실행 결과를 보존하고 `unknown`으로 기록한다.
- 대시보드의 일괄·비교 중지는 취소 요청 파일을 통해 전달한다. runner는 현재 행동·재관찰·평가·단계 기록을 끝내고 종료하며, 이후 세션은 시작하지 않는다.

## 구현 상태

- [x] 관찰 저장 → Brain → ActionExecutor → 재관찰 → 평가 순서로 runner를 변경했다.
- [x] 초기 평가 조기 종료를 제거하고 종료 선언 시 현재 화면을 평가한다.
- [x] 행동·평가 및 미실행 이유를 별도 필드로 기록한다.
- [x] 초기 성공·거짓 완료·실행 실패·후속 관찰 실패·시간 초과·안전 차단의 회귀 검증.
- [x] 행동 중 중지 요청 시 현재 단계 기록 보존과 비교 세션의 미실행 상태를 확인했다.

## 제한

- 기존 페이지 준비 대기와 필수 행동 뒤 재관찰 정책은 유지한다. 범용 렌더링 완료 판정은 별도 작업이다.
- 협력적 중지는 진행 중 행동의 기존 timeout까지 기다린다. OS 강제 종료·프로세스 충돌 시 원자적 기록까지 보장하지 않는다.
- 실제 API와 공개 사이트의 성공은 mock 결과로 주장하지 않는다.
