- 실제 검증: 위 timeout 회귀 4개 통과, 재리뷰에서 중요 미해결 결함 없음. 전체 결과는 verification.md 참고.

## 모델 선택·설정 도우미 회귀

- 증상: 폴링 중 연결 버튼이 다시 활성화되고 미검증 모델도 연결됨으로 표시된다. 추천 토큰 사용량도 다음 폴링에서 사라진다.
- 원인: 서버 키 존재와 모델별 검증을 혼동하고 연결 진행·최근 응답 상태를 유지하지 않았다.
- 해결: 연결 진행 플래그, 모델별 검증 레지스트리, 최근 응답 사용량을 별도로 유지한다. legacy CLI 모델은 명시적인 override가 없으면 보존한다.
- 함께 확인: 모델 변경 후 재검증, 연결 중 중복 요청, 추천 전 자동 적용 없음, 무료 데모의 고정 과업 보존, 실제 선택 모델의 요청·로그 일치.
- 보안 회귀: 질문·대화·문맥 전체의 키/인증 URL과 Unicode 이스케이프된 응답을 검사한다. 임의 DOM selector나 평가 정답을 추천 설정에 넣지 않는다.
- 검증: 유료 API 대신 가짜 응답과 로컬 브라우저로 실패 재현 후 수정했다. 전체 검사 결과는 verification.md에 기록한다.

설정 도우미를 초기 상태 응답 전에 누르면 initialize의 고정 1단계 설정으로 연결 화면이 되돌아갔다. 초기화 시 현재 wizardStep을 보존하도록 바꾸고 지연된 상태 응답으로 재현 검사한다. 작은 화면 모델 안내의 간격을 줄여 연결 버튼과 다음 버튼을 함께 볼 수 있게 했다.

## C/P05 카드 계약 회귀

- 증상: ASCII/100자 카드 제한으로 기존 한글·공백·100자 체크에서 파생된 카드 ID 검토가 거절된다. 같은 관찰 ID의 내용 변경에도 과거 판정이 적용될 수 있다.
- 원인: 카드 ID를 경로 ID와 혼동하고 버전 해시에 근거 내용 대신 관찰 ID만 사용했다.
- 해결: 카드 ID는 기존 issue_id를 그대로 보존한 opaque 문자열이며 경로에 사용하지 않는다. 연결된 관찰 사실을 해시에 포함하고 조회용 URL/스크린샷 경로는 제외한다.
- 함께 확인: 긴/한글 ID, 근거 URL/HTML 변경 시 새버전, 판정/표시URL 변경 시 기존버전, 정상후보0, null행동.
- 실제 검증: 실패 5개 재현 후 계약·보고서 집중 검사25개 통과; 기존 시나리오·회귀 포함38개 통과.

## C/P08 집계 회귀

- 증상: condition이 general/persona로 잘못 남은 scripted 기록을 넣으면 AI 비교 분모가 늘고, 일부 기록의 비용/토큰을 전체0으로 오해할 수 있다. status=null이면 상태 정렬이 실패하고 성공 중앙값에 무한값이 들어갈 수 있다.
- 원인: 실행 유형을 제외하지 않고 알려진 측정값과 누락을 별도로 집계하지 않았다.
- 해결: 명시적 scripted/scenario를 배제하고 전체값·known_total·known/unknown_sessions를 분리한다. 상태 누락은 unknown, 비유효 숫자는 미확인으로 처리하며 성공 중앙값의 대상 수를 전달한다.
- 함께 확인: 성공2/예정5·취소/오류/미실행 보존, 실제0/미확인, provider 부분 토큰, 기록 누락, legacy 조회가 파일을 수정하지 않는지, paired delta 혼동 없음.
- 실제 검사 결과는 verification.md의 P08/전체 검사에 기록한다.

## 최종 통합 검토 보완

- 증상: U+2028/U+2029/U+0085가 들어간 정상 메모를 저장한 뒤 검토 조회와 내보내기가 실패한다.
- 원인: JSONL 쓰기는 원문 Unicode를 보존하지만 읽기의 splitlines는 LF 외의 문자열 내부 구분자도 줄 경계로 처리한다.
- 해결: 검토 이력은 LF 레코드 경계만 파싱하며 손상/부분 이력의 fail-closed 정책은 유지한다.
- 회귀: 세 구분자의 메모/검토자·append/restart/CRLF, 기존 동시저장·손상·키 차단.
- 증상: 사용량이 없는 실제 요청 오류를 토큰0으로 집계하거나 누락 호출의 비용을 전체 비용으로 표시한다.
- 원인: 실행기의 legacy0 계수와 보수적 예산 예약값을 실제 측정값으로 집계했다.
- 해결: 실제 call records 기반 completeness/측정 부분합계와 예산 계수를 분리하고 비교 저장/집계에 전달한다.
- 회귀: missing/partial/error/zero fake 제공자의 로컬 과업→summary→experiment→조회, 기록보다 많은 요청·제공자 누락·소수 비용 측정. 유료 API 검증은 포함하지 않는다.
- 실제 결과는 verification.md의 최종 C 검사에 기록한다.

최종 호환성 확인: 기존 대시보드는 `_run`/`-run`/`.run` ID를 허용하지만 새 레코드가 첫 글자 영숫자만 허용해 저장이 거절됐다. 기존 안전 ID 범위에 맞춰 슬래시는 금지하고 선두 기호를 허용했다. 실패3건 재현 후 계약/저장51개 검사 통과.

## D-01 근거 버전 변경과 입력 폼

- 증상: 카드의 표시 문구는 같지만 근거 버전이 바뀌면 기존 입력 폼이 남고 새 폼이 추가된다.
- 원인: 카드 HTML만 비교해 폼을 교체할지 결정했다.
- 해결: 실행 ID와 카드 ID·버전을 렌더 갱신 기준과 폼 식별에 포함한다. 409 뒤 근거 재조회 시 새 버전에 이전 입력을 적용하지 않는다.
- 함께 확인: 실제 저장·재조회, 5종 판정, 400/404/409/500 실패, 중복 제출, 작은 화면.
- 실제 검증: 새 브라우저 테스트에서 실패 재현 후 12개 통과. 전체 결과는 verification.md에 기록한다.

## D-02 저장 판정이 검토 전으로 되돌아가는 현상

- 증상: 저장은 성공했는데 저장 전에 요청한 자동 갱신 응답이 늦게 도착하면 카드가 잠시 사람 검토 전으로 돌아간다. 같은 실행으로 왕복한 경우 실행 ID만 비교하면 옛 조회를 새 조회로 오인할 수 있다.
- 원인: 선택 실행 ID만 확인하고 저장/선택/명시적 조회 변경 시점을 확인하지 않았다.
- 해결: 상세 조회 변경 번호를 기록하고 현재 번호가 일치할 때만 반영한다. 실행 전환 시 이전 카드 표시를 비우고 대기 갱신은 기존 조회 직후 처리한다. 별칭 입력도 메모와 함께 선택 구간을 복원한다.
- 회귀: 지연 GET 후 판정 유지, A→B→A 중 과거 조회 폐기, 두 실행/카드의 초안 분리, 지연 POST 성공·실패·재시도, 외부 갱신 시 입력 포커스/선택.
- 실제 결과: 구현 전 저장 판정 되돌림 1건 실패 재현. 수정 후 관련 검사 통과. 전체 결과는 verification.md에 기록한다.

## D-03 검토 이력·출처 구분

- 증상: 최신 판정만 보이고 과거 판정의 별칭·시각·근거 버전을 확인할 수 없었다.
- 원인: C API의 전체 reviews와 현재 버전 review_history를 화면에서 펼쳐 읽는 기능이 없었다.
- 해결: 현재/이전 버전을 분리하고 저장 확인 레코드를 즉시 이력에 반영한다. 이력이 바뀌어도 동일 근거 버전 펼침과 입력 초안은 유지한다. 실행 방식과 대상 출처의 누락은 미확인으로 표시한다.
- 회귀: 두 번 저장·재조회, 근거 변경 뒤 현재 미검토/이전 2건, 메모 HTML 이스케이프, 작은 화면 긴 버전, AI/스크립트/Mock/누락 출처, D-02 초안·지연 응답.
- 실제 결과: 구현 전 이력 요소 없음으로 브라우저 검사 실패를 재현했고 수정 후 관련 24개 검사를 통과했다. 전체 결과는 verification.md를 따른다.

## D-04 비교표의 부분 측정값 누락

- 증상: 일부 비용·토큰이 기록돼도 화면에는 미확인만 보이고, 성공 중앙값의 실제 대상 수를 알 수 없었다. 자동 갱신이 상세 펼침을 닫았다.
- 원인: 전체값만 소비했고 known_total/known_sessions/unknown_sessions와 중앙값 대상 수를 사용하지 않았다. 매 조회마다 비교 DOM을 교체했다.
- 해결: C 집계의 전체/부분/coverage와 두 상태 축을 표시한다. 데이터가 같으면 DOM을 유지하고 바뀌어도 실험별 펼침을 복원한다.
- 회귀: 2/5, 성공0/예정0, 취소/미실행, 부분 비용·실제0·전체 누락, 기록0행동/미측정, 중앙값 대상, 기존 실행 연결·없는 버튼 비활성, 좁은 화면, 갱신 뒤 펼침.
- 실제 결과: 기존 화면에서 새 범위 표시를 찾지 못하는 실패를 재현한 뒤 수정했다. 최종 검사 수치는 verification.md를 따른다.
